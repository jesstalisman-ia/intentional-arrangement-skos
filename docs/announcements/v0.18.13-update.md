# v0.18.13 — concepts retire instead of disappearing, language tags behave, and a 9,000-concept thesaurus loads in milliseconds

Sixteen releases have shipped since the v0.17.1 post at the end of August (v0.17.2 through v0.18.13). Most of them answer a ticket or a thread from the people using the editor, and several came in as pull requests. Hard-refresh the editor (Cmd+Shift+R) to pick up the new build; the version badge in the Crosswalk tab should read v0.18.13.

## A retired concept keeps its URI

A published URI is a promise to everyone who indexed against it, so the editor now retires concepts instead of deleting them.

- **Lifecycle status** on every concept: tick **Deprecated (`owl:deprecated`)** and the concept keeps its URI and its place in the scheme; consumers filter it at display time. **Replaced by** records one or more successors as `dcterms:isReplacedBy`, and a change note says why it was retired. Three new checks in Validate keep this honest: a deprecated concept that is still a top concept, a successor that does not exist, and a deprecated concept with narrower concepts but no successor. Deleting or renaming a successor now updates the pointer, so Validate stops reporting a dangling successor after routine edits (#108, @abaronbo).
- **Change log export.** Export → **Change log** writes a `CHANGELOG.md` in [Keep a Changelog](https://keepachangelog.com) style from the recorded edit history: Added / Changed / Deprecated / Removed, dated and credited, with a snapshot of every deprecated concept and its successor. The release heading takes the scheme's `owl:versionInfo`. This is the answer to Doug's [Change Management](https://github.com/jesstalisman-ia/intentional-arrangement-skos/discussions/70) question: patch for editorial fixes, minor for additions, major when indexing has to change, and never a deleted or reused URI.
- **Change notes read like prose again.** A label change no longer quotes `“Day Meal Plan@en”` (#77), approving your own proposal no longer credits you twice (#78), the repair reaches notes imported from earlier exports (#81), and collections record change history the way concepts do (#84). Untagged notes take the scheme language on export (#71).

## Language tags: any BCP 47 tag, one canonical form

The six-language dropdown is gone. Every label, definition, note, document title and comment has one **language-tag field**: a compact box that opens a `code · Name` dropdown and filters as you type, by code or by name, with the scheme default and the tags already in use listed first, then all 183 ISO 639-1 codes. Any valid BCP 47 tag can be typed, `nl-BE` or `zh-Hant` or a three-letter ISO 639-3 code, and a non-tag such as `english` is rejected. Names come from the browser's `Intl.DisplayNames`, so the app stays offline (#107 from @tom-around; #109 and #112 by @abaronbo).

Canonicalisation does only what BCP 47 specifies: letter case (`NL-be` becomes `nl-BE`) and the IANA registry's preferred value for the five deprecated two-letter codes (`iw`, `in`, `ji`, `jw`, `mo`). It never changes the language. An earlier pass had applied CLDR aliases, turning `tl` into `fil` and `cmn` into `zh`; that is reverted (#111). The one rule now lives in the engine, so import, the editor field and the validator agree: an imported `EN` and a typed `en` count as one language (#113), a stored tag that is not canonical raises a warning that shows the canonical form, the scheme's title and description each take a tag of their own so a German title on an English vocabulary stops re-exporting as `@en` (#114), and an agent's `foaf:name` may be tagged (#115, #116).

## Large vocabularies load in milliseconds

@mickbaggen imported the Dutch IMBOR thesaurus, 8,948 concepts, and waited tens of seconds for the tree, for every click, and for every validation pass (#105). Three core operations were quadratic in the number of concepts: the tree helpers re-scanned every concept per rendered node, selecting a concept rebuilt the whole tree, and validation re-scanned all concepts to decide whether each one had narrower terms. All three are now linear. On a synthetic 9,000-concept vocabulary: tree render 5,305 ms → ~14 ms, full validation 5,034 ms → ~50 ms, navigate to a concept 5,114 ms → ~30 ms, with identical output (same tree, same descendant counts, same 181 findings).

## Validate reads more of the SKOS Reference

- **Class disjointness** (S9, S37): one URI is never both a `skos:Concept` and the `skos:ConceptScheme`, or a `skos:Collection`. **Alt-vs-hidden label disjointness** (S13) joins the existing preferred-label checks. **Mapping clash** (S46): `skos:exactMatch` must not share a target with `broadMatch`, `narrowMatch` or `relatedMatch`; when the target is in the same vocabulary the reverse clash is caught too. Imported collections from a foreign namespace keep their URI on export. Contributed by @abaronbo (#102).
- **Label disjointness is compared per exact literal**, as S13 requires: an `altLabel` "hound" and a `hiddenLabel` "Hound" are two literals and legal, and the one-click fix never deletes a casing variant (#103).

## Editing is harder to get wrong

- **Delete a branch, your way.** Deleting a concept with children asks: **Delete, keep children** (they become top concepts) or **Delete all**. A descendant that also sits under a parent outside the branch is kept either way, and ⌘/Ctrl+Z undoes both (#87, @abaronbo).
- **Glossary promotion lands where you are looking.** Promote writes into the taxonomy that is open, and asks before relinking a list that points elsewhere. The parent picker's choice is honored; a native `<select>` was dropping options filled while it opened, so everything used to land as a top concept.
- **UUID identifiers are RFC 9562 UUIDv7**, canonical dashed lowercase, time-ordered so they sort by creation and pair with the change log. **Re-canonicalize existing UUIDs** rewrites older 32-character ids into the dashed form without changing their value, across concept ids, SKOS-XL label URIs and collection ids.
- **Changing the namespace moves everything minted under it**, SKOS-XL label URIs included, so `example.org` stops leaking into published output (v0.18.3).
- **The concept editor never blanks.** Each section renders on its own, so one malformed field shows an inline notice and the rest of the form stays usable (v0.18.4); malformed label arrays are repaired on load rather than isolated (v0.18.8); and the SKOS-XL editor no longer throws on every label (v0.18.10).
- **Sources is a tree with an editor**, like Build: collapsible Documents and Agents groups with counts and a filter, and renames keep a record's place in the export (#98, @abaronbo). The Proposals list refreshes after a submission (#104).

## The supply chain is watched daily

The RDF/XML importer rejects a `DOCTYPE` (entity-expansion guard), the REST API no longer returns exception detail, and the crosswalk and navigation sinks escape every imported label, closing the CodeQL findings (v0.18.0–v0.18.2). Raw `U+FEFF` characters in source became visible escapes. A daily audit checks the Fuseki base-image digest, the SRI hashes and every pinned dependency and files one issue when something drifts; Renovate automerges digest bumps and pins GitHub Actions to commit SHAs. Nothing here changes the app's behaviour, and the app still runs with no network at all.
